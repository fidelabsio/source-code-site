# 2. Email
**Settings → Email**
## 2.1 Choosing how email is sent
<table header-row="true">
<tr>
<td>Option</td>
<td>What it means</td>
</tr>
<tr>
<td>App default</td>
<td>Emails send through this app's own built-in mail sender. Nothing to configure — works immediately.</td>
</tr>
<tr>
<td>Gmail</td>
<td>Send using the merchant's own Gmail account (address + an app password, not the regular account password).</td>
</tr>
<tr>
<td>Elastic Email</td>
<td>Send using the merchant's own Elastic Email account (address + API credentials).</td>
</tr>
<tr>
<td>Custom SMTP</td>
<td>Send through any mail server — host, port, username, password, and whether the connection is secure.</td>
</tr>
</table>
Whichever option is chosen, the merchant also sets a **From Name** and **From Email** — what a customer sees as the sender. A **Send test email** action confirms the setup works before relying on it. Passwords/credentials entered here are encrypted before they're saved.
## 2.2 Which emails actually send
Four toggles, each independent:
<table header-row="true">
<tr>
<td>Toggle</td>
<td>Sends when…</td>
</tr>
<tr>
<td>Notification email</td>
<td>A customer submits a new quote request — sent to the merchant</td>
</tr>
<tr>
<td>Auto-response email</td>
<td>A customer submits a new quote request — sent back to the customer as confirmation</td>
</tr>
<tr>
<td>Accept-quote email</td>
<td>The merchant accepts a quote and chooses to email the customer</td>
</tr>
<tr>
<td>Reject-quote email</td>
<td>The merchant rejects a quote and chooses to email the customer</td>
</tr>
</table>
## 2.3 Email Template Editor
Each of the four email types above has its own editable subject, heading, message, and button text, with placeholders like `{customer_name}` or `{product_title}` that get filled in automatically. Once a merchant saves a custom template here, it's used for every future email of that type on their store — replacing the app's built-in default text just for them.

# 4. General Settings
**Quote Settings → Quote Settings tab** (unless noted otherwise)
## 4.1 How to Control Which Products Get a Quote Button
1. Go to **Quote Settings**.
2. Under **Targeting**, choose one: **All products**, **Specific products** (pick them individually), or **Rule-based** (e.g. by tag, product type, or vendor).
3. If rule-based, add one or more conditions and choose whether a product must match **all** of them or **any** of them.
4. Optionally, restrict the whole thing to specific collections only.
5. Optionally, turn on **Require login** so only signed-in customers see the button.
6. Optionally, list storefront URLs to exclude entirely, even if a product on that page would otherwise qualify.
7. Click **Save**.
## 4.2 How to Hide Prices on Specific Pages
A separate rule system from the quote button above — a merchant can use one, both, or neither.
1. Still on **Quote Settings**, find the **Hide Price** section.
2. Choose the scope: **All products**, **No products**, **Specific products**, or **Rule-based** (same rule-builder as 4.1, but independent — it can target a different set of products than the quote button does).
3. Tick which page types the hiding applies to: product pages, collection pages, the homepage, and/or the cart page.
4. Choose what shows instead of the price: custom text (e.g. "Price available on request", edit the wording here) or nothing at all.
5. Click **Save**.
## 4.3 How to Change the Button, Popup, and Its Behavior
1. Choose where the button sits on a product page (e.g. directly below Add to Cart).
2. Turn on/off whether it also shows on collection pages and the homepage (see the Feature Flags in section 5 for the exact switches).
3. Choose what happens on click: open the popup form directly, add the product to a running "quote cart" first, or both.
4. Edit the button's own label, the popup's title, its submit-button text, and the message shown after a successful submission — each is a plain text field.
5. Turn on/off the product image, the step indicator, and the trust-signal lines inside the popup, and edit what those trust-signal lines say.
6. Click **Save**.
## 4.4 How to Set Where Customers Land After Submitting
1. Set **Redirect after adding to quote** — where a customer goes right after adding a product to their quote cart.
2. Set **Redirect after submit** — where they go after the quote form itself is submitted.
3. Set **Continue shopping link** — where a "Continue shopping" link sends them.
4. Leave any of the three blank to keep the customer on the same page instead of redirecting them.
5. Click **Save**.
## 4.5 How to Set the Notification Email
1. Find **Notify email** on the Quote Settings page.
2. Enter the address that should receive an alert every time a new quote comes in.
3. Click **Save**.
This is a different setting from the sender identity ("From Name"/"From Email") configured in section 2 — this one is *who receives* the alert, that one is *who it looks like it's from*.
## 4.6 How to Build the Quote Request Form
1. Go to **Quote Settings → Form Builder** (the second tab).
2. Pick a section: **Contact info**, **Shipping info**, or **Extra info**.
3. Click **Add field**, then pick a type — short text, paragraph, email, phone, date, dropdown, radio buttons, checkbox, number, file upload, or a plain instructional paragraph.
4. Fill in that field's label, placeholder text, and help text, plus any type-specific options (dropdown/radio choices, number min/max, accepted file types, etc.).
5. Toggle **Required** if the customer must fill it in before submitting.
6. Drag fields to reorder them, or remove ones that aren't needed.
7. Separately, toggle whether product vendor, SKU, variant option, catalog price, and the customer's own quoted price show as read-only details on the form, and whether a per-product note field is offered.
8. Click **Save**.
## 4.7 How to Configure PDF Options
1. Go to **Settings → PDF**.
2. For each quote status (e.g. new, accepted), choose what that status's downloadable PDF includes.
3. To change the PDF's actual template content — its title, description, header/footer text — click through to the **PDF Template Editor** linked from this page.
4. Click **Save**.

# 6. Branding & White Label
A different audience from sections 2–5: not a per-shop merchant setting, but a one-time setup done by whoever deployed this app instance, before any merchant ever installs it. It's done by editing plain JSON files under `app/config/` — no `.js` code is touched, and it satisfies the same "no core code changes" requirement as everything else in this guide.
## 6.1 How to Change the App's Name
1. Open `app/config/branding.json` in the project.
2. Find the `APP_NAME` key.
3. Replace its value with the new name, e.g. `"APP_NAME": "Acme Quotes"`.
4. Save the file.
5. **Restart the app** — stop and restart the dev server, or redeploy in production. This particular file is only read once, when the server starts, so a save alone isn't enough.
6. Reload the admin. The new name now shows everywhere the app displays its own name: email headers, the pre-install login/landing pages, dashboard copy, the Settings page sidebar, and the PDF title fallback.
## 6.2 How to Add a Logo and Signature to Emails
1. Open the same file, `app/config/branding.json`.
2. Set `EMAIL_LOGO_URL` to a public image URL (must be reachable over the internet — a link to a file on your own computer won't work).
3. Set `EMAIL_SIGNATURE` to whatever line of text should appear under the footer of every email, e.g. `"— The Acme Quotes Team"`.
4. Save the file and restart the app, same as 6.1 — this file is cached at startup too.
5. Send a test email (Settings → Email → Send test email) to confirm the logo and signature appear.
**Both changes together:**
```diff
{
-  "APP_NAME": "Quote Request",
-  "EMAIL_LOGO_URL": "",
-  "EMAIL_SIGNATURE": "",
+  "APP_NAME": "Acme Quotes",
+  "EMAIL_LOGO_URL": "https://cdn.example.com/acme-logo.png",
+  "EMAIL_SIGNATURE": "— The Acme Quotes Team",
}
```

## 6.3 How to Change Colors
1. Decide what you want to recolor, and find the matching file in the table below — e.g. "the admin's primary button" is `app/config/app-shell/theme.json`.
2. Open that file.
3. Find the specific key for the thing you want to recolor — each one has a `usedIn` field describing exactly what it touches, so you can confirm you've got the right one.
4. Change its `"value"` to a new hex color code, e.g. `"#7c3aed"`. Leave `usedIn` alone — it's a description for humans, not something the app reads.
5. Save the file.
6. Reload the admin page. Most of these apply immediately; `email/theme.json` is the one exception and needs a restart (see the table).
There's no single theme file — colors are split one file per admin page, so each can be recolored independently. Every key follows the same shape: `{ "value": "#hexcode", "usedIn": "what this reaches" }`.

<tr>

<tr>

<td>Dashboard stat cards, checklist, progress bar</td>
<td>Immediately</td>

<tr>

**Example — change the primary admin button color** (`app-shell/theme.json`):
```diff
{
  "ADMIN_BUTTON_BRAND_COLOR": {
-   "value": "#1a1a18",
+   "value": "#7c3aed",
    "usedIn": "..."
  }
}
```

## 6.4 How to Change Admin/Email Copy and Text
Alongside colors, each admin page (except `app-shell` and `quote-settings`, which have no editable copy) has a matching `text-labels.json` — page headings, button labels, empty-state text, and, for `email/text-labels.json`, the default subject/heading/content for each transactional email type.
1. Find the right file, e.g. `app/config/dashboard/text-labels.json` for Dashboard copy, or `app/config/email/text-labels.json` for email defaults.
2. Open it and find the text you want to change — keys are nested and named after where the text appears (e.g. `templates.notification.subjectDefault`).
3. Edit the string value. Leave the key name itself alone.
4. Save the file and reload the admin — no restart needed for these.
**Example — change the default subject line for new-quote notification emails** (`app/config/email/text-labels.json`):
```diff
"notification": {
-  "subjectDefault": "New quote request from {customer_name}",
+  "subjectDefault": "New quote from {customer_name}",
}
```
<callout icon="ℹ️" color="gray_bg">
	Email template text is only the **shipped default** for a new, uncustomized shop. A merchant who has already saved their own version in Settings → Email Templates keeps their own — editing this file doesn't touch an existing merchant's live templates.
</callout>
