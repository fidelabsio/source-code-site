<callout icon="🎨" color="blue_bg">
	This guide is for buyers of this source code who want to rebrand the app — name, colors, logo, and email content — without touching any `.js` code. Every setting described here lives in a plain JSON file under `app/config/`.
</callout>
<callout icon="⚠️" color="yellow_bg">
	**The rule:** edit the `.json` files. Never edit the matching `*.server.js` file next to it — that file only reads the JSON and hands the values to the rest of the app. If a `.server.js` file needs editing, that's a bug, not a customization.
</callout>
This guide is scoped to **brand identity** — app name, favicon, colors, buttons, email sender/templates/footer. It does not cover general UI copy (page headings, button labels, empty-state text), which lives in separate `text-labels.json` files per admin page; see section 5 for where that is.

# 2. Brand Configuration Guide
## 2.1 App Name — app/config/branding.json
```json
{
  "APP_NAME": "Your Store Name",
  "EMAIL_LOGO_URL": "",
  "EMAIL_SIGNATURE": ""
}
```
<table header-row="true">
<tr>
<td>Key</td>
<td>Controls</td>
<td>Default if blank</td>
</tr>
<tr>
<td>`APP_NAME`</td>
<td>The product's display name — shown in transactional-email headers, the pre-install login/landing pages, dashboard onboarding copy, the Settings page sidebar, and the PDF/print-view document-title fallback</td>
<td>"Quote Request"</td>
</tr>
<tr>
<td>`EMAIL_LOGO_URL`</td>
<td>A publicly reachable image URL shown in the header of every transactional email (notification, confirmation, accept, reject, merchant reply, GDPR data-access), in place of the plain store name</td>
<td>blank — no logo shown</td>
</tr>
<tr>
<td>`EMAIL_SIGNATURE`</td>
<td>A signature line shown under every transactional email's footer (see 2.3 — Footer)</td>
<td>blank — no signature shown</td>
</tr>
</table>
This is the **only** file that controls the software vendor's own product name across the app. It's separate from a merchant's per-shop settings (Quote Settings, Email/PDF template content) — those are a different, already-complete customization system for the person installing the app, not for the person selling it.
<callout icon="💡" color="blue_bg">
	**Favicon** — there is no `FAVICON` key. The browser-tab icon for the standalone pre-install landing and login pages (the ones outside the Shopify admin iframe) is `public/favicon.svg`, referenced by path in `app/root.jsx`. Replace that SVG file directly; it isn't config-driven.
</callout>
## 2.2 Colors & Buttons — the theme.json files
There is no single `theme.json`. Colors are split one file per admin page, so each page can be recolored independently without side effects on the others. All of them share the same shape:
```json
{
  "SOME_COLOR_KEY": {
    "value": "#hexcode",
    "usedIn": "plain-English description of what this reaches"
  }
}
```
`usedIn` is documentation, not read by the code — edit `value` only.

## 2.3 Email — Colors, Templates, Sender
Three separate concerns live under `app/config/email/`, plus one setting that is deliberately **not** in a config file.
**Colors** — `app/config/email/theme.json`:
```json
{
  "EMAIL_HEADER_COLOR": "#1a1a18",
  "EMAIL_CTA_COLOR": "#1a1a18",
  "EMAIL_ACCEPT_COLOR": "#1a7f4b",
  "EMAIL_REJECT_COLOR": "#4a4a48",
  "EMAIL_EDITOR_LINK_COLOR": "#2c6ecb"
}
```
<table header-row="true">
<tr>
<td>Key</td>
<td>Controls</td>
</tr>
<tr>
<td>`EMAIL_HEADER_COLOR`</td>
<td>Header background for notification/auto-response emails</td>
</tr>
<tr>
<td>`EMAIL_CTA_COLOR`</td>
<td>Button background for notification/auto-response emails</td>
</tr>
<tr>
<td>`EMAIL_ACCEPT_COLOR`</td>
<td>Header + button background for every "quote accepted" email</td>
</tr>
<tr>
<td>`EMAIL_REJECT_COLOR`</td>
<td>Header + button background for every "quote rejected" email</td>
</tr>
<tr>
<td>`EMAIL_EDITOR_LINK_COLOR`</td>
<td>Link color inside the Email Template Editor's own admin UI (not inside the sent email)</td>
</tr>
</table>
These are fixed vendor-set colors, independent of anything a merchant configures — kept separate from every other `theme.json` since email rendering has its own constraints (inline styles only, email-client quirks).
**Templates** — `app/config/email/text-labels.json`, under its `templates` key, holds the shipped default subject/heading/content/button text for the four transactional email types (`notification`, `auto-response`, `accept-quote`, `reject-quote`), plus the merge variables each supports:
```json
"notification": {
  "subjectDefault": "New quote request from {customer_name}",
  "headingDefault": "New Quote Request!",
  "contentDefault": "You have a new quote request from {customer_name} for {product_title}. {quote_message}",
  "actionDefault": "View Quote",
  "variables": [
    { "key": "{customer_name}", "desc": "Full name of the customer" }
  ]
}
```
<callout icon="ℹ️" color="gray_bg">
	These are only the **shipped defaults**. Once a merchant edits a template in **Settings → Email Templates**, their edit is saved per-shop in the database and takes over from this file for that shop — editing this JSON changes what a *new, uncustomized* shop sees, not an existing merchant's live templates.
</callout>
**Footer** — there is no dedicated "footer" config. What renders at the bottom of every transactional email is:
1. A fixed line: `Sent to {email} via {store_name}` (not configurable — the recipient address and the merchant's own store name).
2. `EMAIL_SIGNATURE` from `branding.json` (section 2.1), shown underneath it when set.
**Sender** — the "From Name" / "From Email" a customer sees is a per-shop merchant setting (**Settings → Email → SMTP**), stored in the database, not a JSON file. Each shop sets its own sender independently of this app instance's own branding. It's excluded here for the same reason merchant Quote Settings are: it belongs to whoever installs the app, not to whoever sells it.

# 3. Configuration Examples
### Rename the app
`app/config/branding.json`:
```diff
- "APP_NAME": "Quote Request",
+ "APP_NAME": "Acme Quotes",
```
Restart the server — this file is cached at startup (section 1).
### Add a logo and signature to transactional emails
`app/config/branding.json`:
```diff
- "EMAIL_LOGO_URL": "",
- "EMAIL_SIGNATURE": "",
+ "EMAIL_LOGO_URL": "https://cdn.example.com/acme-logo.png",
+ "EMAIL_SIGNATURE": "— The Acme Quotes Team",
```
Restart the server. Every transactional email now shows the logo in its header and the signature line in its footer.
### Change the primary admin button color
`app/config/app-shell/theme.json`:
```diff
  "ADMIN_BUTTON_BRAND_COLOR": {
-   "value": "#000075",
+   "value": "#7c3aed",
    "usedIn": "..."
  }
```
Reload the admin — no restart needed. This reaches every admin page, since it's set once in the root layout.
### Recolor the "quote accepted" email
`app/config/email/theme.json`:
```diff
- "EMAIL_ACCEPT_COLOR": "#1a7f4b",
+ "EMAIL_ACCEPT_COLOR": "#059669",
```
Restart the server — email colors are cached at startup (section 1).
### Change a template's default subject line
`app/config/email/text-labels.json`, inside `templates.notification`:
```diff
- "subjectDefault": "New quote request from {customer_name}",
+ "subjectDefault": "New quote from {customer_name}",
```
Reload the admin — no restart needed. Only affects shops that haven't yet saved their own copy of this template in Settings → Email Templates.
### Replace the favicon
Not JSON. Overwrite `public/favicon.svg` with a same-named SVG file. No restart or config edit needed — it's served as a static asset.
